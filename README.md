# b24-app

Внутреннее приложение для портала `umniydom.bitrix24.ru`. Оно добавляет в Битрикс24 собственные рабочие экраны для сделок, каталога, снабжения, складских операций, инвентаризаций, ремонтов, маркетплейсов, отчётов и договоров.

Актуальная документация начинается с [docs/README.md](docs/README.md). Развёртывание, подключение к Битрикс24 и откат описаны в [docs/runbook.md](docs/runbook.md).

## Текущая схема

- Битрикс24 хранит CRM-сущности: сделки, контакты, компании, задачи, файлы и пользовательские поля.
- ERPNext работает как закрытое складское ядро: каталог, цены, склады, остатки и складские документы.
- Backend на Node.js связывает Битрикс24 с ERPNext и отдаёт frontend.
- React-приложение открывается внутри Битрикс24 через placement API.
- Прод работает на одном корпоративном VPS `201.51.12.57`.
- Публичная точка входа: `https://201.51.12.57.sslip.io`.
- ERPNext и backend не публикуются напрямую в интернет: к ним обращается nginx или соседний контейнер.

Подробная схема — в [docs/architecture.md](docs/architecture.md) и [docs/network.md](docs/network.md).

## Структура репозитория

```text
packages/
  backend/   Fastify, OAuth, placement-роуты, API Битрикс24 и ERPNext
  frontend/  React SPA, которая открывается в iframe Битрикс24
  shared/    общие TypeScript-типы
deploy/      проверенные конфигурации VPS, nginx и ERPNext
scripts/     служебные, диагностические и миграционные инструменты
docs/        документация
```

## Разработка

Требуется Node.js 20 или новее.

```bash
npm ci
npm run dev:backend
npm run dev:frontend
```

Проверка перед коммитом:

```bash
npm run typecheck
npm -w @b24-app/backend test
npm run build
```

Локальные переменные окружения создаются по образцу [packages/backend/.env.example](packages/backend/.env.example). Секреты, токены и рабочие `.env` в репозиторий не добавляются.

## Правила изменений

1. ERPNext является источником складских остатков. Старые скрипты миграции нельзя запускать как регулярный синк.
2. Записывающие скрипты и API-проверки нельзя запускать на проде без понимания их области действия.
3. Изменение пользовательского поведения сопровождается обновлением документации в том же коммите.
4. Перед продом обязательны typecheck, тест backend и build.
5. При деплое предыдущий контейнер сохраняется для быстрого отката.

# Денежные итоги инвентаризации по рознице

Пользователь подтвердил расчёт по розничной цене. По каждому складу под отправленным отчётом показываются отдельно положительные суммы недостачи и излишков. Они не сальдируются. В раскрытых расхождениях добавлены розничная цена и сумма строки, в Excel — оба итога на листе «Сводка» и цена/сумма на листе «Товары».

При отправке на проверку сервер сравнивает явно введённые факты с неизменяемым снимком учёта, затем читает через официальный ERPNext API цены Item Price из Standard Selling в RUB. Цена сохраняется в каждой строке расхождения, вместе с результатом и существующим submittedAt. Последующие изменения каталога не переоценивают отчёт. Цена клиента игнорируется; повторный submit уже отправленного результата отклоняется. После возврата в работу и новой отправки формируется новый результат с новой ценой.

Сумма строки = модуль расхождения × сохранённая розничная цена, с округлением до копеек. Суммы складываются раздельно по знаку расхождения. Явная нулевая цена допустима. Отсутствующая, отрицательная, валютная или неоднозначная цена не подменяется нулём: соответствующий итог помечается неполным, в Excel остаётся пустым, рядом указано число строк без цены. При недоступности источника цен отправка завершается ошибкой без записи нового статуса; ранее сохранённый черновик остаётся.

Старые отчёты не заполняются сегодняшними ценами. Если сохранённой цены нет, применяется та же отметка неполноты. На возвращённой в работу точке денежная сводка явно относится к последнему отправленному отчёту; она не пересчитывается по промежуточному черновику. Excel также помечает эту разницу, а изменённым фактам не присваивает цену прежнего результата.

## Хранение и будущая выкладка

Подготовлена миграция 0113_add_inventory_result_retail_price.sql: nullable DECIMAL(21,9) в inventory_result_lines. Чтение, запись, нормализация и Bitrix-представление сохраняют optional retailPrice. Отсутствующее поле не добавляется в старые записи и не меняет их прежние state hash.

Миграция НЕ запускалась. Production не изменён. Перед будущим разрешённым запуском новой версии в SQL-режиме требуется применить 0113 в установленном порядке, с резервной копией отдельной БД приложения и проверкой существующей схемы. Автоматические миграции на старте не добавлены.

Важно для отката: после появления новых результатов с retailPrice старый SQL-reader без этого поля не сможет проверить их state hash. Простое переключение обратно на старый контейнер нельзя считать безопасным откатом для таких данных. Перед выкладкой необходим отдельный проверенный план отката: совместимый reader либо согласованное восстановление БД и связанных зеркал/журналов из резервной копии. Не удалять цены и не переписывать хеши автоматически ради отката. Сохранение rollback-контейнера, сеть ERPNext и три проверки из AGENTS.md остаются обязательными.

## Проверки

- test:inventory-money: 36 backend и 9 frontend тестов. Серверная цена против подделки клиента, неизменность цены, отказ источника без записи отчёта, неподсчитанные позиции, пропуски, нулевая цена, отдельные суммы и копейки, SQL чтение/запись и state hash, повторное открытие реального XLSX в памяти.
- npm test --workspaces --if-present: все наборы прошли, включая pretest; основные наборы — 444 backend и 140 frontend.
- npm run build и npm run typecheck: успешно. Остаётся предупреждение Vite о размере bundle.
- Локальный браузер: компонент сводки проверен на тестовых данных с обеими суммами, отсутствующей ценой и без расхождений. Временная страница удалена, тестовые сервер и вкладка закрыты. Реальные инвентаризации не отправлялись.
- Интеграционный тест MariaDB расширен ценой и миграцией 0113, но НЕ выполнялся: локальный Docker недоступен из текущего окружения. Проверка миграции на реальной тестовой БД остаётся обязательной перед выкладкой.

Изменение подготовлено поверх ebbcd2f (обязательный общий комментарий к заказу) и 378eb83 (Excel), в изолированной рабочей копии ветки codex/inventory-excel-export. Все три доработки остаются локальными: пользователь запретил выкладку до следующей команды.

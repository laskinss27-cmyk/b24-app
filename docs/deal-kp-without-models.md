# КП без названий моделей

Решение заказчика 05.10.2026: в клиентском КП можно оставить общие названия товаров без модели и бренда (например, «IP-камера Hikvision DS-2CD…» → «IP-камера»). Фото, количества, единицы измерения, цены после скидок, суммы и названия работ сохраняются. Исходный состав сделки и каталог не редактируются.

Кнопка «Печать» заменяет выпадающее меню «Документы». Небольшое модальное окно содержит прежние действия: КП в PDF, Word, Excel, товарный чек и договор. Флажок «Без названий моделей» доступен только для КП и выключен при каждом открытии. После подтверждения PDF открывается в прежнем просмотре, Word/Excel скачиваются; чек и договор используют прежние сценарии и ограничения доступа. Формируется текущий открытый вариант КП, как прежде.

## Данные и совместимость

- `/api/deal/kp` принимает необязательный строгий boolean `withoutModels`. Без него прежний ответ и режим сохраняются.
- Состав/количества/цены берутся из прежнего плана ERPNext или выбранного альтернативного варианта. Сначала выполняется прежняя свёртка исходных позиций, затем меняется только печатное имя товара и убирается подпись артикула. Разные модели с одинаковым общим названием и ценой остаются отдельными строками во всех форматах.
- Для нового режима модель, артикул и бренд читаются адресным read-only запросом из ERPNext `Item.b24_model`, `b24_article`, `b24_brand`, включая архивные товары. Раньше КП использовал сведения о моделях из каталога Б24; обычный режим и источник фотографий остаются прежними. Если Item отсутствует, используются доступные старые сведения Б24. Ошибка запроса идентичности ERPNext останавливает формирование без моделей, а не выдаёт обычное КП под видом скрытого.
- Из наименования удаляются известные модель, артикул и бренд с границами слов, затем коды с буквами и цифрами для старых/ручных строк. Основные числовые характеристики, IP-класс и Cat.6 сохраняются. Если остаётся только код, печатное название — «Оборудование».
- Свободное название без заполненной модели/бренда может содержать нераспознаваемое словесное название модели. Это ограничение автоматического разбора; перед отправкой клиенту нужен просмотр готового КП. Фото сохраняются по решению заказчика и могут содержать маркировку.
- Word/Excel получают подготовленный ответ с флагом `withoutModels`; повторная нормализация не объединяет уже обезличенные строки. Миграция данных не нужна.

## Проверки

Регрессии входят в обычные наборы: `B/deal-kp-models.test.ts` (разбор, Word/Excel, отдельные одинаковые названия, суммы/единицы), `B/deal-manual.test.ts` (HTTP, скидки, неизменность источника и работ), `F/deal-commercial-proposals.test.ts` (флаг и активный вариант во всех форматах).

Браузерная проверка: запустить Vite на localhost:5183, затем `node tools/kp-print-ui-test.mjs`. Локальный стенд `packages/frontend/kp-print-preview.html` не подключён к production entry; тест блокирует внешние запросы и подменяет API. Он проверяет PDF/Word/Excel, обычный режим, чек/договор, Escape, возврат фокуса, узкую ширину, увеличение текста и тёмную тему.

Локальная проверка 05.10.2026: полные наборы backend (454 проверки) и frontend (198) прошли, `npm run typecheck` и `npm run build` успешны. Браузерный тест прошёл в headless Edge на ширинах 360, 768 и 1280 px, включая увеличение текста вдвое, тёмную тему, клавиатуру и возврат фокуса. Результаты Word/Excel проверены по содержимому сгенерированных файлов; визуальная проверка в Microsoft Word/Excel, экранным диктором и на production не выполнялась. Выкладка не входит в эту локальную проверку.

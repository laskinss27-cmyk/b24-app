# Ротация резервных копий ERPNext на Диске Б24

`scripts/core-backup-disk.ts` остаётся входом ежедневного задания. Реализация —
`scripts/core-backup-retention.mjs`. Обрабатываются только файлы в корне общего
диска (storage ID 3; override `CORE_BACKUP_DISK_STORAGE_ID`) с точным именем
`YYYYMMDD_HHMMSS-frontend-database.sql.gz`. Вложенные папки, документы, фото,
копии заказов и `b24_app_backups` не обрабатываются.

Сохраняется последняя копия за каждую из последних 14 **дат, за которые есть
бэкап**, плюс последняя за каждый из шести календарных месяцев, включая текущий.
Все копии моложе 48 часов дополнительно защищены. Разреженная история не удаляется
только потому, что копия старше 14 календарных дней.

Перед очисткой свежая локальная копия (не старше 48 часов) должна совпасть с самой
новой копией на Диске: имя, размер, родительская папка, SHA-256 скачанного файла и
целостность gzip. Уже загруженная копия повторно не загружается. Если загрузка,
проверка или чтение списка не удались, удаления не начинаются. Проверяются все
страницы списка и сохранность оставляемых файлов; удаляемые файлы перечитываются
непосредственно перед удалением. Задание останавливается при неоднозначном ответе.

Удаление через `disk.file.delete` окончательное, чтобы освобождать место без
накопления в корзине. Семантика метода:
https://apidocs.bitrix24.ru/api-reference/disk/file/disk-file-delete.html
План, проверенный SHA, намерение и результат каждого удаления записываются с fsync
в `core-disk-retention.jsonl` рядом с локальным дампом, без токенов и download URL.
Там же создаётся исключающая параллельный запуск `.core-disk-retention.lock`;
после аварийного завершения lock требует ручной проверки процесса перед снятием.

## Применение

Все пути ниже нужно подтвердить на сервере. Из каталога с настроенным dotenv:

```sh
npx tsx core-backup-disk.ts --plan /confirmed/path/20260927_090004-frontend-database.sql.gz
npx tsx core-backup-disk.ts --apply /confirmed/path/20260927_090004-frontend-database.sql.gz
# Обычный вызов cron: загрузка, проверка, затем ротация
npx tsx core-backup-disk.ts /confirmed/path/20260928_090004-frontend-database.sql.gz
```

Это отдельное обслуживание host-side backup job, а не выпуск backend-контейнера.
Устанавливать оба скрипта только из чистого, отправленного Git-коммита, сверив
SHA-256. Сохранить прежний загрузчик перед заменой; сначала установить модуль,
затем атомарно заменить входной `.ts`. Проверки:
`node --test scripts/core-backup-retention.test.mjs`, реальный `--plan`, `--apply`,
повторный `--plan` без кандидатов на удаление и неизменность ежедневного cron.
Другие файлы production-приложения и контейнеры не переключаются.

# Очистка Docker на production

Политика согласована 15.09.2026: работающие сервисы, образы заданий каталога и Тильды, **две последние разные версии b24-app для отката**. Старые остановленные контейнеры b24-app и их неиспользуемые образы удаляются. Данные, тома, bind mounts и резервные копии не удаляются.

## Реализация

- Исходник: `scripts/b24-docker-retention.py`, тесты: `scripts/test_b24_docker_retention.py`.
- На сервере: `/usr/local/sbin/b24-docker-retention.py`.
- Планировщик: `b24-docker-retention.timer`, каждый час с задержкой до 5 минут; сервис запускает скрипт с `--apply`.
- Кэш сборок сокращается до 2 GB командой Buildx; занятый сборкой кэш может временно превышать лимит.
- Новые образы, недавно остановленные контейнеры и первый час после запуска backend защищены часовым интервалом. Это предотвращает удаление подготовленной версии во время деплоя. После него следующая очистка применяет обычное ограничение.
- Без `--apply` скрипт только рассчитывает кандидатов и проверяет здоровье backend.
- После успешного деплоя и обязательных проверок запустить сервис; если новая версия работает менее часа, очистку выполнит таймер позже.

## Защита

Сохраняются образы **всех** оставшихся контейнеров, включая сторонние сервисы. Отбираются только контейнеры b24-app с известными префиксами и образы принадлежащих приложению репозиториев (включая старые `b24-backend` и `cr.yandex/crpj8ipjmjimigbf8dq7/b24-app`). Старые образы без тегов определяются по проверенной комбинации `/app`, команды `node packages/backend/dist/server.js` и порта `8080/tcp`; образы с неизвестной принадлежностью сохраняются. Образ с дополнительным тегом чужого репозитория сохраняется. Контейнеры с Docker-томами не удаляются. Метка `b24.retention.keep=true` позволяет явно закрепить контейнер/образ для особого случая; после окончания работ её нужно убрать.

Образы заданий определяются из активного root crontab и скриптов `/root/sync/tilda-stock-sync-job.sh`, `/root/sync/b24-app-catalog-sync-job.sh`. При исчезновении задания или невозможности определить его образ очистка завершается ошибкой. При изменении способа запуска этих заданий нужно одновременно обновить определение защищённых образов и проверить dry-run.

Перед удалением проверяются работающий `b24-backend`, сеть `erpnext_frappe_network`, HTTP `/health`; во время очистки повторно проверяются контейнер backend, ссылки планировщика и использование образов. Удаление без принудительного режима, без удаления томов и без автоматической очистки родительских образов. Параллельные запуски блокируются файловой блокировкой. Секреты окружения и содержимое заданий не выводятся в журнал.

## Команды на сервере

```sh
/usr/local/sbin/b24-docker-retention.py
systemctl start b24-docker-retention.service
systemctl status b24-docker-retention.timer
journalctl -u b24-docker-retention.service --since yesterday
docker system df
df -h /
```

Отключить только расписание: `systemctl disable --now b24-docker-retention.timer`.
Не использовать `docker system prune -a` или очистку томов: задания каталога и Тильды используют образы без постоянного контейнера.

Таймер обслуживает инфраструктуру; он не обновляет приложение, не запускает миграции и не меняет задания каталога/Тильды.

## Результат очистки 15.09.2026

Удалено 290 остановленных контейнеров и 385 образов, кэш сборок очищен. Фактически свободное место выросло с 16.08 до 56.47 GB (освобождено около 40.39 GB); заполнение диска снизилось с 81% до 32%.

Осталось 15 работающих контейнеров и ровно два контейнера отката, всего 14 образов с учётом сервисов, откатов и заданий. Сохранены откаты `inventory-reopen-20260914` и `inventory-list-20260910`, образы Тильды `a146a81` и каталога `4e0b8f0`. Образы отдельного сервиса заказов в эту очистку не включались.

Подтверждено: исходные ID работающих контейнеров, образы и подключения данных не изменились; все 8 томов и root crontab сохранены; внутренний и публичный `/health` вернули 200; аутентифицированный read-only запрос к ERPNext вернул 200; нужная Docker-сеть подключена. Десять защитных тестов прошли локально и на сервере. Служба очистки завершилась с `Result=success`, таймер включён и активен. Повторный dry-run: 0 контейнеров и 0 образов к удалению.

Машинный отчёт: `outputs/docker-retention-20260915/verification.json`. Исходный снимок на сервере: `/var/lib/b24-docker-retention/before-20260915.json` (без переменных окружения и секретов).

После подтверждения готовности рабочего приёмника:

1. Передать стороне b24-app только фактический sourceId существующей установки
   сайта. Не менять identity и не переносить реальные заказы в тестовую базу.
2. Получить подтверждённый HTTPS URL с путём
   `/api/integrations/umniydom/v1/orders` и новый общий секрет через защищённый
   канал. Секрет не включать в переписку, Git или вывод команд.
3. Изменить только настройки транспорта существующего сайта. Сохранить
   контракт, исходящую очередь, eventId/order.id, повторную передачу тех же байтов,
   проверку квитанции и статусы заказов.
4. После отдельного разрешения выполнить один согласованный контрольный заказ.
   Сначала подтвердить accepted и устойчивую запись на b24-app; после разрешения
   обработки — привязку к клиенту/лиду и уведомление в «Заказы интернет магазин».

HTTP accepted означает надёжный приём, а не принятие заказа менеджером.
Лиды по умолчанию принадлежат «Автозадачи»; свободный менеджер берёт лид сам.
При неоднозначном совпадении клиента новый лид не создаётся, уведомление
«Нужен ручной разбор» поступает в тот же чат.

# Услуги без реализации — решение 01.10.2026

По прямому решению пользователя услуги полностью исключены из реализации в «Товарах 2.0». Повод — услуга проектирования №9916 в сделке 32686: отсутствие складского документа блокировало технический признак готовности, хотя услуга не списывает оборудование. Пользователь уже провёл документ самостоятельно; этот документ не отменяется.

## Действующее поведение

- Услуги остаются в рабочем составе, этапах, КП, договоре и общей сумме сделки. Цена, скидка и количество редактируются как прежде, с сохранением защиты существующих связей.
- В строке услуги нет выбора для реализации и поля отгрузки; подпись — «без реализации». Общий выбор и создание Delivery Note включают только товары. Старый клиент не может создать реализацию услуги через `/api/deal/realize-core`: тип проверяется сервером.
- `UF_CRM_ALL_REALIZED` проверяет только товары. Сделка с непустым составом из одних услуг удовлетворяет этому условию без Delivery Note. Пустая сделка не становится готовой автоматически. Одинаковые товары проверяются по сумме количеств; черновики не считаются, возвраты уменьшают выполненное количество.
- После изменения состава/проведения товаров действует обычная синхронизация признака. При открытии старой сделки с услугами сверка может убрать прежнее `НЕТ`, если товары полностью проведены. Сверка ограничена открытой сделкой, повторно проверяет состояние CRM и идентичность состава и читает документы без присвоения исторических сегментов. Этап, деньги, остатки и ERP-документы этим действием не меняются. Массовой смены признаков старых/закрытых сделок нет.

## Источник отчёта

`buildSalesReport` выбирает успешно закрытые сделки по полным московским датам закрытия. Товары по-прежнему считаются по проведённым Delivery Note и знаковой себестоимости Stock Ledger Entry (FIFO); неполная себестоимость не превращается в ноль.

Сумма услуг берётся из текущего рабочего состава выбранной успешно закрытой сделки — черновика Sales Order с `b24_deal_id`, с ценами/скидками этапов и остатком основной строки. Повторяющиеся строки сохраняются; количество этапа распределяется один раз. Прибыль услуг остаётся оценкой по `profit_coef`; расходники не дают прибыль. Сделка из одних услуг без товарных проводок имеет известную нулевую прибыль товаров. Это не доказательство фактических затрат на услуги.

Историческое правило «услуга попадает в отчёт только после проведённой реализации» **намеренно отменено**. Исторические реализации услуг и возвраты сохраняются, но их суммы не добавляются вторично к составу сделки. Если рабочий план старой сделки отсутствует, используется прежний расчёт услуг по проведённым документам; отсутствующий план не выдумывается. Повреждённый состав, неизвестный тип позиции или цена дают ошибку чтения, а не фиктивный ноль.

Новый источник применяется и к ранее закрытым сделкам с существующим планом. Отдельный снимок состава на момент закрытия не создаётся: последующая допустимая правка плана меняет сумму услуг при следующем чтении отчёта. Данные не перепроводятся и не мигрируются. Нативная свёрнутая строка Битрикс24 не является источником выручки услуг.

## Совместимость и проверки

Старые документы остаются в истории и доступны существующим средствам работы с документами; низкоуровневые функции ERP для совместимости/восстановления не удалены. Защиты идентичности строк, цены полностью возвращённой истории, складского количества, прав и конкурирующих черновиков сохранены. Реализация услуги, уже созданная до обновления, не удаляется автоматически.

Штатные регрессии:

- `backend/src/deal-fulfillment.test.ts`: услуги без документов, смешанный состав, дефицит/черновик/возврат товара, дубли количества, безопасное обновление старого признака.
- `backend/src/routes/deal-service-realization.test.ts`: старый клиент не создаёт сервисный документ, серверный тип приоритетнее клиентского флага, записи ERP отсутствуют.
- `backend/src/erp/closed-deal-services.test.ts`: цены/скидки этапов и повторяющиеся услуги, расходники, отсутствие/повреждение плана, успешно закрытая сделка без документа, исключение двойного учёта старого документа.
- `backend/src/admin/deal-document-diagnostics.test.ts`: нескладская услуга с историческим складом не считается дефицитом товара.
- `frontend/src/deal-services.test.tsx`: отсутствие отгрузочных элементов услуги, сохранение редактирования, исключение услуги из устаревшего выбора при сохранении товарной реализации.

Пути относительно соответствующего `packages/`. Все регрессии обнаруживаются обычными workspace-командами; существующие тесты товарных проводок/возвратов остаются в полном наборе.

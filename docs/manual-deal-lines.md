# Ручные строки КП

В подборе товаров сделки и варианта есть «Добавить вручную»: название, единица,
количество, цена и скидка. Карточка каталога не создаётся; снабжение, резерв и
реализация недоступны. Для закупленного товара менеджер удаляет строку и
добавляет позицию каталога самостоятельно.

Ручные строки имеют `manual: true`, уникальный отрицательный `productId` как
внутренний идентификатор строки и `lineKey`. Положительные ID остаются только
у каталога. Отрицательные ID исключены из запросов остатков и каталога;
`ensureCoreItem` отклоняет их до любых операций ERP.

Хранение: `${B24_STATE_DIR:-/app/state}/deal-manual/<dealId>.json`, атомарная
замена файла. Каталоговые строки остаются в Sales Order. Общие методы чтения
плана и расчёта суммы объединяют оба источника. Это позволяет начать сделку
только с ручных строк, без фиктивного ERP Item или пустого Sales Order.

При первом использовании ручных строк варианты этой сделки переносятся из
поля Sales Order в тот же файл состояния. После этого файл остаётся источником
вариантов, даже если менеджер удалил все ручные строки. Он также сохраняет
варианты при удалении последнего каталожного товара. Существующие сделки без
ручных строк продолжают использовать прежнее хранение вариантов.

Каталог ERP и постоянный каталог `/app/state` должны восстанавливаться из
согласованной резервной копии. При развёртывании сохраняется существующий
bind mount состояния; файлы `deal-manual` не являются кэшем.

Проверки: `npm -w @b24-app/backend test`, `npm -w @b24-app/frontend test`,
`npm run typecheck`. Тесты ручных строк используют временное состояние и
поддельный ERP, не обращаясь к рабочим сделкам.

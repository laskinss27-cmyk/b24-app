## Что предотвращает повторение

| Сценарий | Защита штатного процесса | Предел гарантии |
|---|---|---|
| Ручная правка или забытый файл вне Git | Грязный/staged/untracked checkout и неопубликованный HEAD блокируются; сборка берёт только Git archive | Владелец root/Docker технически может обойти штатный сценарий; это запрещено правилами проекта, но не системой разграничения полномочий |
| Сборка/выкладка не той версии | Полный SHA и tree сравниваются между Git, OCI и манифестом; закреплён точный image/container ID | Это проверка происхождения, не криптографическая подпись |
| Потеря файлов при полном rebuild | Source guard сравнивает исходники текущего production и кандидата; хеши обнаруживают ручные изменения контейнера | Удаление условия внутри существующего файла проверяется тестами и ревью, а не списком файлов |
| Повторная потеря восстановленных правил | Регрессионные сценарии входят в автоматически обнаруживаемый штатный набор; тесты обязательны внутри release build | Зелёные тесты подтверждают покрытые сценарии, не все возможные сочетания production-данных |
| Неработающая версия после переключения | Два health-check с SHA, сеть, чтение ERPNext, сохранённый rollback и откат при провале проверок | Health и read-only ERP-проверка не заменяют сквозную пользовательскую приёмку каждой функции |

Не применять точечные копирования в контейнер, сборку поверх работающего образа или ad hoc stop/run. Новые правила и изменения поведения фиксировать вместе с тестами и обновлением реестра; уменьшение покрытия разбирать явно. Эти требования уже закреплены в AGENTS.md и [release-provenance](../release-provenance.md).

Абсолютная гарантия отсутствия любых будущих регрессий не заявляется. Открытые расхождения INV-04/INV-06 из исходного аудита не закрываются этой выкладкой; их поведение в этом релизе не менялось.

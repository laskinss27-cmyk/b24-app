# Расходные материалы: действующее правило

Правило **PRICE-02** из [реестра](feature-registry.md) восстановлено в Git `1b58dd396bda7a091f3eec8f61ac95db49425465` и выложено 29.09.2026. Исходная реализация `04b9e37` была выложена 07.09.2026; прежняя ссылка на локальную папку outputs не является источником спецификации.

## Поведение

- Основная карточка — **18612**, родитель — **18610**, историческая услуга-дубль — **9254**. Определяем их по ID, не по названию. Транспортные расходы и прочие материалы автоматически к расходникам не относятся.
- В каждой строке сделки эффективная закупка равна **цене продажи единицы после скидки**. При изменении цены/скидки закупка следует за строкой; количество масштабирует обе суммы одинаково. Нулевая продажа даёт нулевую закупку. Прибыль расходников равна нулю.
- Правило одинаково для исходного состава, этапов, старых услуг и отчёта продаж. Выручка не исчезает из отчёта.
- Это расчёт конкретной строки. Общая закупочная цена карточки, оценка ERP и исторические приходы этим правилом не перезаписываются.
- 9254 скрывается в новом выборе. Исторические ID и документы не заменяются и не объединяются; ERP Item не требуется отключать.
- Ручные строки без карточки — отдельная возможность, а не расходники по названию.

## Код и проверка

Общий контракт: [consumables.ts](../packages/shared/src/consumables.ts), функции isPassThroughProduct, dealLinePurchasingPrice, isRetiredConsumablesProduct.

Регрессионные проверки: [frontend](../packages/frontend/src/consumables.test.tsx) и [отчёт backend](../packages/backend/src/b24/sales-report-consumables.test.ts). Проверяют скидку, ноль, несколько единиц, этапы, историческую услугу, скрытие дубля и раскрытие состава из ядра. Команды: `npm -w @b24-app/backend test`, `npm -w @b24-app/frontend test`.

Ручной контроль: расходники 1 × 1000 со скидкой 10% должны дать продажу 900, закупку 900, прибыль 0; при количестве 2 обе суммы 1800. Обычный товар в той же сделке сохраняет свою закупку.

чат **«Менеджеры Умный дом», chat3092**. Старый chat19572 сохранён с историей;
новые уведомления интеграции туда больше не направляются.

## Правило Битрикса

Создано необязательное строковое поле лида `UF_CRM_UMNIYDOM_BRIDGE`, ID 2954,
XML_ID `umniydom-orders-bridge-v1`, название «Интеграция заказов магазина».
При создании нового лида адаптер устанавливает `umniydom-orders-v1`.
Ответственный — «Автозадачи», 2812; статус NEW. ORIGINATOR_ID/ORIGIN_ID сохранены.
Существующих клиентов адаптер не обновляет, их источники и история сохраняются.

В шаблон автоматизации NEW, ID 34, перед прежними ветками уведомлений добавлена
одна пустая ветка: поле точно равно `umniydom-orders-v1`. Стандартная «Новая
заявка» для такого лида пропускается; подробное сообщение отправляет интеграция.
Все прежние действия и условия источников, распределение остальных уведомлений
по ответственным и чатам сохранены. Это подтверждено сравнением экспорта до и
после: единственное изменение — новая первая ветка. Пауза робота осталась 5 секунд.

Неоднозначные клиенты также направляются в chat3092 для ручного разбора; новый
лид автоматически не создаётся. Заказ существующего клиента даёт новое сообщение
с прежней ссылкой CRM. При длинном заказе сообщение может состоять из нескольких
частей; это предусмотренные части одного уведомления, а не повторная отправка.

## Что остаётся перед запуском для покупателей

Маршрут уведомлений настроен и проверен. Постоянные отправка сайта и CRM-worker
по-прежнему выключены; контрольные заказы обработаны по одному. Временный файл
вебхука на сервере очищен после каждого запуска. Для постоянной работы нужны
согласованный служебный вебхук с доступом к CRM и chat3092, включение отправки
сайта и отдельное включение worker. Это не часть текущего изменения маршрута.

При переносе на другой портал сначала создать поле указанного типа и настроить
исключение робота. Проверить поле через `scripts/check-orders-bitrix.mjs`;
не полагаться на молчаливое принятие неизвестного UF-поля REST API.

Права менеджеров на взятие лида будут проверены при готовности к эксплуатации.
На этапе строительства дополнительных участников не добавляли.

# Персональная выгрузка артикула и закупки

Первоначальный формат выложен 05.10.2026: `5893df5`. [Проверки и границы приёмки](audits/2026-10-05-marketplace-purchase-export.md).

Решение владельца 05.10.2026: Сергею Посягину, подтверждённый Bitrix ID `3712`,
разрешена только выгрузка «артикул — закупка» из «Маркетплейсы → База товаров».
Это отдельное дополнение к [складским правам](warehouse-access-editor.md),
не назначение отдела снабжения или общего доступа к редактированию каталога.

Позднее 05.10 владелец добавил в разрешённый файл старый ID и наименование,
чтобы сотрудник мог узнавать товары. Это заменяет первоначальный формат из
двух колонок; при следующем скачивании формируется четыре колонки. Старые
скачанные файлы не изменяются, миграция данных не требуется.

Существующая кнопка Excel и маршрут `/api/catalog/export-marketplace-selection`
сохраняются. Сервер получает ID через OAuth `user.current`, игнорирует переданные
клиентом роли и ID. Для `3712` всегда создаётся один лист с четырьмя колонками:
«Старый ID», «Артикул», «Наименование», «Закупка, ₽». Клиент не может переключить его на полный формат.
Другие сотрудники с прежними правами получают прежнюю полную выгрузку.
При отказе в правах ошибка теперь говорит о доступе; при недоступной проверке
пользователя выгрузка закрыта с временной ошибкой 503.

Источник данных не меняется: выбранные в интерфейсе ID сопоставляются с текущим
каталогом ERPNext через `buildCoreProductBase`, артикул — `Item.b24_article`,
старый ID — `Item.b24_marketplace_old_id`, наименование — существующее
нормализованное имя товара из `Item.item_name`, закупка — существующий механизм
текущей закупочной цены каталога. Отсутствующий старый ID остаётся пустым и не
заменяется текущим ID. Старый ID сохраняется текстом с ведущими нулями. Это не оценка
исторических документов. Повторные ID удаляются, неизвестные товары и услуги
не попадают в файл. Отсутствующая цена остаётся пустой, а не нулевой. Артикулы
с ведущими нулями и знаками формулы сохраняются как текст. Другие поля каталога
и скрытые листы в узкий файл не записываются.

Исключение действует только в этом серверном маршруте чтения. Проверки создания
и редактирования карточек, цен, операций маркетплейсов, закупочных разделов и
политика складских прав не изменены. Существующая проверка видимости закупочных
цен сохраняется. Данные, отделы и документы не мигрируются. Отмена персонального
разрешения требует изменения правила и обычного выпуска приложения.

Регрессия `packages/backend/src/routes/api-catalog-export.test.ts` проверяет
реальный XLSX после HTTP-запроса, четыре столбца без других данных, выбранные товары,
пустую цену и старый ID, текстовые идентификаторы, наименование, невозможность подмены личности/формата, отказ при
ошибке OAuth, запреты изменения карточек/цен и прежний полный файл снабжения.
Тест входит в штатное рекурсивное обнаружение backend-тестов.

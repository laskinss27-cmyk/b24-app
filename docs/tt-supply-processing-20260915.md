# Обработка заявок ТТ — 15 сентября 2026

В рабочем b24-app включена обработка заявок снабжению из «Снаб → Входящие заявки ТТ». Ранее заявки типа supply имели только просмотр: создание перемещения поддерживало другой тип документа.

## Для снабжения

1. Открыть заявку и нажать «Обработать заявку».
2. Проверить конечный склад, указать крайнюю дату поставки. Для ручных позиций выбрать товар каталога. Количества сохраняются из исходной заявки.
3. Нажать «Передать в обеспечение». Создаётся Material Request в ERPNext; приложение открывает его в «Обеспечение и заказы».
4. Использовать существующий процесс распределения между закупкой и перемещением и контроля исполнения. В исходной заявке остаётся ссылка «Открыть обеспечение».

До передачи доступна отмена по существующим правам. После начала передачи отмена исходной заявки блокируется, чтобы не потерять связь с документом ERP.

Заявки 21388, 21186, 20684 и 20662 оставлены в исходном состоянии. За них не выбраны сроки или решения о закупке. У 20684 две ручные позиции: DHI-VTO6222E-P и DHI-VTH1020J; снабжению нужно сопоставить их с каталогом. Комментарий о предварительном согласовании цен и сроков сохранён.

## Реализация и восстановление

POST /api/transfer-requests/process-supply требует текущую авторизацию и существующее право transfers.manage_requests. Права пользователей не расширялись. Обработка, отмена и прежнее преобразование в перемещение используют общий mutex заявки.

Перед отправкой в ERP в существующем JSON заявки сохраняется supplyHandoff: уникальный заголовок, подготовленное содержимое, время и автор. После успешного создания сохраняются supplyRequestName и статус converted. Исходные строки, ссылки, количества и комментарии сохраняются. Схемы SQL и ERP при выпуске не мигрировали.

Если ответ ERP потерян, «Проверить передачу» ищет единственный неотменённый Material Request по точному уникальному заголовку. Повторный POST создания автоматически не выполняется. Ноль, несколько результатов или отменённый документ требуют ручной сверки: проверить ERP и сохранённый supplyHandoff, определить фактический результат, затем восстановить связь. Не удалять маркер и не пересоздавать документ вслепую.

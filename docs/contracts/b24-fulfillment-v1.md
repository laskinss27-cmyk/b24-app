# Получение заказа в `order.created` v1

Приёмник b24-app принимает необязательное поле `order.fulfillment`, не меняя
`schemaVersion: 1`. Старые события без поля остаются действительными.

Допустимы только два строгих варианта:

```json
{ "fulfillment": { "method": "pickup" } }
```

```json
{
  "fulfillment": {
    "method": "delivery",
    "address": "Санкт-Петербург, Невский проспект, дом 1"
  }
}
```

Точный контракт:

- `fulfillment` находится внутри `order`;
- объект строгий, дополнительные ключи запрещены;
- `method` равен только `pickup` или `delivery`;
- при `pickup` поле `address` отсутствует;
- при `delivery` поле `address` обязательно;
- адрес обрезается по краям, содержит 5–500 символов и не содержит управляющих
  символов U+0000–U+0008, U+000B, U+000C, U+000E–U+001F;
- остальные поля, endpoint, sourceId, секрет, hash и идемпотентность v1 не меняются.

В уведомлении менеджеру pickup отображается как
`Получение: Самовывоз · точку и время уточнить`. Для delivery выводятся строки
`Получение: Доставка` и `Адрес: ...`. Недоверенный адрес экранируется тем же
механизмом, что комментарий. Старое событие без поля отображается как
`Получение: Не указано · уточнить у клиента`.

Данные сохраняются только в неизменяемом входящем снимке. Они не записываются в
поля, источник или комментарий лида и не создают доставку, резерв, оплату, счёт,
курьерскую задачу или выбор точки самовывоза. Старые события не перестраиваются
и повторно не отправляются.

Production receiver и постоянный worker b24-app обновлены 18.09.2026. Магазин
может обновлять витрину и свой постоянный orders worker для новых событий.

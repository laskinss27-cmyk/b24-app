# Совместный тест сайта и b24-app

Дата: 14.09.2026. Результат: **sandbox-тест пройден**.
Рабочая отправка не включена, реальных лидов и сообщений не создавали.

## Что запускали

Сайт: настоящий `checkoutQuote` / `submitOrder`, SQLite `OrdersStore`, исходящая
очередь, `deliverNext` и HTTP-транспорт. b24-app: настоящий отдельный HTTP-приёмник
`integrations/umniydom/cli.ts serve` и его обработчик `once` с `MockOrdersCrm`.
Это не повторная отправка статического JSON вместо кода сайта.

Обе базы созданы заново во временном каталоге. Фактический `sourceId` установки
прочитан из `state/orders.sqlite` через read-only соединение и использован только
для идентичности временного отправителя и настройки временного приёмника.
Рабочую identity не меняли; заказы и контакты из рабочей базы не копировали.
Контакты, товары и промокод — вымышленные данные из примера контракта.

Приёмник слушал случайный порт на `127.0.0.1`, режимы принудительно
`sandbox` / `mock`. Случайный общий секрет существовал только в памяти и окружении
дочерних процессов; в файлы, аргументы и вывод не записывался. Вебхук CRM пустой.
По завершении дочерние процессы остановлены, временные базы удалены.
Репозиторий b24-app, ERP, Тильда и параметры работающего сайта не менялись.

## Проверенные сценарии

1. Оформление заказа с TEST10: 2 × 1500 ₽, скидка 300 ₽, итог 2700 ₽.
   Повтор оформления с тем же requestId не создаёт второй заказ.
2. Получатель записал заказ и ACK; тест намеренно скрыл ответ от отправителя.
   Сайт оставил доставку в `retry`, а не потерял заказ.
3. Перезапущены приёмник и хранилище отправителя. Повтор передал те же байты,
   UUID и sourceId, получил прежнюю квитанцию; сайт сохранил `accepted`.
4. Ещё 20 параллельных отправок вернули один и тот же ACK. Осталась одна запись
   inbox; повторный запуск обработчика не добавил лид или уведомление.
5. Первое уведомление в mock содержит ссылку на тестовый лид, товар, промокод,
   итог и «Яндекс Карты», признак теста. Полученный снимок равен снимку сайта.
6. Второй заказ того же покупателя привязан к первому mock-лиду. Ручной товар
   сохранил `manual-UUID`, неизвестный итог — `null`, текст — «цена по запросу».
7. Итого: **2 заказа, 1 mock-лид, 2 mock-уведомления**. Оба задания b24-app —
   `done`; обе доставки сайта — `accepted`. Статусы заказов сайта остались `new`:
   доставка уведомления не означает принятие заказа менеджером.

Дополнительно прошли все **20 тестов интеграционного модуля b24-app**, включая
неоднозначное совпадение клиентов, защиту от повторной записи при неопределённом
результате CRM, проверки токена/режима/хеша и запрет смены назначения базы.

На стороне сайта также прошли `npm run format:source`, `npm run format:check`,
`npm run build`, полный `npm test` и синтаксическая проверка обоих новых скриптов.

## Повторный запуск

Нужны Node.js 24+, установленные зависимости обоих репозиториев и реализация
приёмника в локальном b24-app. Из корня сайта:

```powershell
npm run orders:test-joint -- D:/Projects/b24-app
```

Необязательный второй аргумент — путь к существующей базе заказов сайта, из
которой разрешено **только чтение идентичности**. По умолчанию `state/orders.sqlite`.
Отсутствующая база/identity — ошибка, новый рабочий sourceId тест не создаёт.
Тест не требует секретов production или запущенных серверов сайта. Ничего не
нужно вручную переключать в `.env`. Для другого компьютера указать его локальный
путь к репозиторию b24-app.

Сценарий находится в `scripts/smoke-b24-orders.mjs`, управление дочерними процессами
отделено в `scripts/order-integration/receiver.mjs`. В обычный `npm test` этот
межрепозиторный тест намеренно не включён: соседний репозиторий не обязателен
для разработки сайта.

## Границы результата и следующий этап

Проверена совместимость кода и контракт v1 через настоящий loopback HTTP.
Браузерное оформление в этом тесте не выполнялось; вызывается серверный сервис
оформления. CRM заменена штатным mock, поэтому права реального вебхука, доступ
к чату, фактические совпадения клиентов и автоматизации портала этим тестом не
подтверждены. Рабочая интеграция пока выключена; поступающие сейчас тестовые
заказы сайта автоматически в b24-app не отправляются.

Перед production остаются пункты из `b24-app/docs/umniydom-orders.md`:
совместить модуль с актуальной производственной веткой (сохранить SQL catalog-mirror),
согласовать HTTPS-адрес и отдельный секрет, постоянную БД и резервирование,
настроить и проверить выделенный вебхук/чат/ответственного/начальную стадию.
Сначала запуск приёмника с `PROCESSOR=off`, включение live-обработчика — отдельное
согласованное действие. Тестовые базы не переносить в production.

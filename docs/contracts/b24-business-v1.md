# Необязательные реквизиты организации в `order.created` v1

Приёмник b24-app принимает совместимое расширение существующего события.
Отправитель может добавить в `order` поле `business`, не меняя `schemaVersion: 1`:

```json
{
  "business": {
    "name": "ООО «Пример»",
    "inn": "7812345678",
    "kpp": "781201001",
    "details": "р/с 40702810000000000001 в банке ..."
  }
}
```

Точный контракт:

- частный заказ не содержит ключ `business`;
- `business` — строгий объект без дополнительных ключей;
- `name` — строка после trim длиной 2–200 символов;
- `inn` — строка из 10 или 12 цифр;
- `kpp` — пустая строка либо строка из 9 цифр;
- `details` — строка после trim длиной до 2000 символов, пустая разрешена;
- email для счёта передаётся в существующем `order.contact.email`;
- остальные поля, заголовки, подпись тела и правила идемпотентности v1 не меняются.

Старые сохранённые события без `business` продолжают приниматься. Их не нужно
изменять или повторно отправлять. Production receiver и worker b24-app обновлены
18.09.2026; сторона магазина может отдельно включить отправку новых событий.

b24-app сохраняет объект в неизменяемом входящем снимке и показывает менеджеру
название, ИНН, непустой КПП и дополнительные реквизиты. Контактом остаётся человек.
Эти данные считаются заявлением покупателя: приёмник не подтверждает организацию,
не объединяет компании по ИНН, не создаёт компанию или счёт и не записывает
реквизиты скрытым комментарием в лид.

## Совместимый откат

Нельзя просто запускать старый контейнер после появления новых результатов с ценами: старый reader не учитывает retailPrice в state hash.

Подготовлен image b24-app:6d21525-inventory-20260908-rollback-compatible. Это непосредственно предыдущий production image, в котором заменены только четыре скомпилированных SQL-модуля model.js, reader.js, writer.js и read-shadow.js на новые совместимые версии. Старые интерфейс и бизнес-маршруты сохранены; чтение/запись и зеркалирование понимают новое optional поле. Проверено чтение всех существующих инвентаризаций без изменения их хешей. Этот image используется автоматическим аварийным откатом скрипта переключения.

При ручном откате:

- Сначала подтвердить актуальные контейнеры и режимы, сохранить текущий контейнер и effective env; использовать тот же /app/state, локальный порт, restart policy и сеть ERPNext.
- Запускать совместимый rollback image, а не старый контейнер напрямую. Исходный старый контейнер оставить для расследования.
- Не откатывать 0113, не удалять цены, не переписывать state hash и не восстанавливать старый dump поверх текущих данных.
- Повторить internal/public health, ready, официальный ERP read, SQL inventory read и network inspect. Любое восстановление БД с потерей новых изменений требует отдельного согласования.

Операционные скрипты и обезличенные результаты находятся в outputs/inventory-excel/ops основной рабочей папки; серверные логи сборки и резервного копирования — в root-only каталоге текущей операции. Старые документы о локальной подготовке являются историческими: запрет выкладки снят этой явной командой пользователя.

# Временный просмотр вложений Telegram (MSG-09)

Решение владельца 09.10.2026: кнопки «Просмотр» и «Прослушать», без постоянного хранения скачанных файлов. Закрытие просмотра/вкладки требует повторной загрузки при следующем открытии. Текст сообщений, привязки к контактам и оригиналы Telegram не удаляются.

## Поведение

- Новые голосовые помечаются «Голосовое сообщение», аудиофайлы — «Аудиофайл». Старые сохранённые записи с общей отметкой вложения используют кнопку «Просмотр»; тип содержимого определяется при загрузке и аудио также открывает проигрыватель.
- Поддержаны JPEG/PNG/WebP/GIF, PDF, OGG/MP3/M4A/WAV/WebM audio и MP4/WebM video. Возможность воспроизведения конкретного кодека зависит от браузера. Для неподдержанных форматов, исчезающих сообщений, удалённых файлов и файлов больше 25 МБ интерфейс предлагает Telegram. HTML/SVG и произвольные URL не выдаются как активный контент.
- Одновременно открыто только одно вложение. Нет кнопки постоянного скачивания, импортера, автоматической предзагрузки и записи в localStorage/IndexedDB/Cache Storage. Автопроигрывание не включается.
- Закрытие окна просмотра (кнопка/Escape), переключение диалога/клиента/мессенджера, отзыв доступа, скрытие документа, pagehide/unmount отменяют загрузку и отзывают object URL. IntersectionObserver, ResizeObserver и проверка размера документа каждые 500 мс обнаруживают скрытый iframe при смене нативной вкладки Битрикс24. Очистка выполняется напрямую, поскольку React может отложить перерисовку скрытой вкладки; браузер может замедлять таймеры. Медиа останавливается и освобождает src. Поздний ответ после закрытия отбрасывается. Новое открытие всегда делает новый запрос.
- Это освобождение временных ссылок/буферов приложения, а не обещание криптографического стирания RAM, ОС swap или файлов, самостоятельно сохранённых пользователем средствами браузера.

## Источник данных, доступ и ограничения

Прежний источник истории остаётся прежним: encrypted SQLite + контактная модель MSG-08. В базе сохраняются только сообщения/метаданные. Для нового просмотра добавлен POST `/api/telegram/media`: OAuth текущего сотрудника, действующий `deals.view`, доступ к сделке и её контакту, принадлежность аккаунта/диалога контакту, существующее неудалённое сообщение с вложением. Номер чужого сообщения/диалога не является разрешением.

Сервер берёт свежую запись Telegram для исходного peer и message ID и проверяет peer ещё раз: пользовательские Telegram ID сообщений не подменяют проверку диалога. Свежая запись даёт актуальный file reference. Скачивание выполняется через существующую сессию только в Buffer, без outputFile и файлов на диске. После загрузки повторно проверяются контакт CRM, состояние подключения и сообщения. Нет webhook fallback или публичного URL вложения.

Ответ: `Cache-Control: private, no-store, max-age=0`, `Pragma: no-cache`, `X-Accel-Buffering: no`, MIME allowlist и nosniff. Браузер использует authenticated POST с `cache:no-store`, проверяет формат и размер и создаёт временный Blob URL. PDF рисуется постранично в canvas через лениво загружаемый PDF.js: без исполнения скриптов PDF, интерактивных форм и ссылок. Worker и canvas уничтожаются при закрытии, в том числе через AbortSignal до отложенного React unmount. Парольные/повреждённые и некоторые специальные PDF могут потребовать Telegram. Reverse proxy должен уважать X-Accel-Buffering; body/request логирование для media не добавлялось.

Лимит 25 МБ проверяется по Telegram metadata, прогрессу и итоговому Buffer; браузер дополнительно ограничивает поток ответа. На сервере до двух скачиваний одновременно, до одного на аккаунт. Ожидание ограничено 90 секундами, библиотеке передаётся AbortSignal. Прерывание ответа, отключение аккаунта и завершение сервиса отменяют работу. FLOOD_WAIT соблюдается штатным механизмом; новый запрос не обходит паузу Telegram.

## Проверки и совместимость

`media.test.ts`: память/отсутствие outputFile, свежая ссылка, peer mismatch, TTL, формат, размер, отмена, изоляция контакта/сообщения, параллельность, удаление в процессе, права до и после загрузки, no-store, неизменность SQLite. `telegram-media.test.ts`: освобождение Object URL, повторная загрузка, поздний ответ, авторизованный POST, запрет кэша, формат/размер. Они входят в штатные discovery suites.

Browser regression (включая фактическую отрисовку PDF и завершение worker) в `tools/telegram-pilot/contact-ui-test.mjs`: собранный frontend, реальный audio element на синтетическом WAV, закрытие/Escape, повторная загрузка, отмена ожидающего ответа, скрытый родительский iframe и pagehide. Прочие MSG-08 regression scenarios сохранены.

Просмотр сам по себе не меняет схему SQLite или шифрование; отдельные добавочные таблицы MSG-11/12 описаны в telegram-account-lifecycle.md. Старые сообщения совместимы. Возврат предыдущего релиза просто убирает просмотр, временные файлы мигрировать или чистить на диске не нужно. WhatsApp/MAX в эту реализацию не входят.

Результаты локальной проверки: [602 backend / 210 frontend и browser](audits/2026-10-09-telegram-accounts-preview-local.md). Выложено 09.10 в `4a04c1e`; реальный PDF проверен. [Отчёт выпуска](audits/2026-10-09-telegram-accounts-release.md).

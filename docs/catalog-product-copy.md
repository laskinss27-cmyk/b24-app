# Копирование карточки товара без фото

Решение владельца 09.10.2026: снабжение создаёт новую карточку на основе существующей, включая комплекты. Доступ назначен Даниилу Андропову (78) и Марку Иванову (3606); закреплённые администраторы 1858/1 также могут пользоваться действием. Имена, активность и отдел 10 подтверждены user.get 09.10.2026. Совпадение имени, общий отдел, portal ADMIN и клиентский userId права не дают.

## Пользовательский сценарий

Снабжение → Остатки (также база маркетплейсов или общий каталог) → карточка → «Копировать без фото». Открывается форма с полным названием, производителем, моделью, артикулом, разделом, розницей, закупкой, статусами, описанием и структурированными характеристиками/категорией фильтра. Сотрудник правит нужное, нажимает «Создать товар» и видит отдельную карточку с новым ID. До сохранения записей нет; исходная карточка не редактируется. Сохранённая копия не добавляется автоматически в корзину продажи.

Фото не переносится даже при подмене payload; в форме копирования нет загрузки фото. Добавить собственное фото позже можно обычным редактированием карточки с прежними правами. Не копируются остатки, резервы, цены проведённых документов, движения и старый внешний ID маркетплейса. Новая карточка имеет нулевой физический остаток.

Комплект в текущем ERP — складская Item с одним исходным товаром и количеством единиц. Сервер читает действующие b24_bundle_source_product/b24_bundle_units при открытии и сохранении; форма позволяет изменить исходный обычный товар и целое количество от двух. Копирование сохраняет только эти справочные поля, без Repack, Stock Entry или проведения. Вложенные комплекты, услуги, отключённые/отсутствующие компоненты блокируются. Веб-комплекты КП из интеграции сайта, не являющиеся карточками каталога, к этому действию не относятся.

Старые комплекты часто не имеют производителя/модели: копирование не требует придумывать эти значения. Полное название редактируется отдельно, максимум 140 символов. Неизвестная закупка остаётся пустой и требует ввода; ноль возможен только явно. Проверка дублей по имени/модели сохраняется, дополнительно читается ERP, даже когда Bitrix/cache недоступен. После успешного создания повтор с тем же именем блокируется как дубль. При неопределённой отправке следует найти новую карточку, не менять имя ради повторной отправки.

## Доступ, источники и совместимость

- UI получает canCopyProduct из /api/catalog/browse; оба маршрута copy-details и create-product с copySourceId заново вызывают OAuth user.current и проверяют точный ID. Общий create без copySourceId продолжает работать по прежнему правилу. Новая возможность не включает общий редактор нескладских ролей ACCESS-01/05 и не меняет нативные ACL Битрикса.
- Текст/характеристики/цены формы берутся из открытого каталога (ERP + существующие метаданные Bitrix), затем пользователь явно сохраняет их. Источник типа карточки и связей комплекта — свежая ERP Item. Изменение исходной карточки после открытия формы не подменяет введённые пользователем значения.
- Новый ID выдаёт catalog.product.add. Сначала запись токеном сотрудника; только при определённом Access Denied возможен существующий CATALOG_WRITE_WEBHOOK для разрешённого копирования. Другие ошибки не повторяются через системную запись. Это расширяет прежнее узкое исключение Константина только на данное действие, без расширения его прежних общих прав.
- Затем штатное создание ERP Item и Item Price, нормализация контента/фильтров; журнал содержит actorId и copySourceId. Новых таблиц/миграции нет. Старый код читает копии как обычные Item/комплекты; откат кода не удаляет созданные карточки.
- Сериализация создания остаётся в одном процессе backend. Полная распределённая идемпотентность, межсистемная транзакция Bitrix/ERP и восстановление частичного инфраструктурного отказа этим изменением не вводятся.

Браузерный сценарий tools/catalog-copy-ui-test.mjs проверяет собранный раздел Снабжения (readOnly + allowCreateProduct), редактирование/отправку обычной карточки и комплекта, отсутствие фото, показ нового ID, скрытие кнопки без права, ширину 1280/390. Данные синтетические; production карточки для теста не создаются. Реальный read-only обзор подтвердил 92 комплекта и наличие системного writer. [Выпуск](audits/2026-10-09-catalog-copy-release.md).

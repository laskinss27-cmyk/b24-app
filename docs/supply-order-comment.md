# Один обязательный комментарий к заказу из сделки

В форме «Заказ снабжению» остаётся только общий комментарий (1–500 символов после удаления пробелов по краям). Поля комментариев к отдельным позициям и их временное состояние удалены. Кнопка создания недоступна при пустом поле; обработчик отправки и API повторно валидируют значение. Переносы строк внутри комментария сохраняются.

POST `/api/supply/request` требует общий `note`, не принимает непустые комментарии строк от старого клиента и сообщает о необходимости перенести их в общее поле. Новая форма отправляет только ID, имя и количество товара в каждой строке. Старые записи и их комментарии не удаляются и не мигрируются. Низкоуровневые ERP-читатели и исторические представления сохраняют совместимость.

При редактировании общего комментария в снабжении также нельзя сохранить пустое значение: проверка есть в форме, frontend API и POST `/api/supply/request-note`.

Проверки: `test:supply-comments` обоих пакетов, общие тесты backend/frontend, сборка и typecheck. В локальном браузере проверена сама форма: одно поле комментария, пустое поле блокирует создание, заполненное разрешает. Проверка выполнялась на временном примере без создания реальных заявок.

Подготовлено поверх `378eb83` (экспорт инвентаризации в Excel) в `codex/inventory-excel-export`. Оба изменения пока НЕ выложены. Пользователь явно запретил выкладку до дальнейшего указания.

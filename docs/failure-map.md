# Карта отказов

## Зависимости

| Узел | Что перестаёт работать | Что продолжает работать | Первое действие |
|---|---|---|---|
| Битрикс24 | вход пользователей, CRM-контекст и REST-вызовы | backend и ERPNext могут быть технически здоровы | проверить статус портала и не повторять записи вслепую |
| nginx или TLS | все наши окна недоступны снаружи | backend и ERPNext доступны локально на VPS | сравнить внешний и внутренний health |
| `b24-backend` | наши экраны и API | стандартные разделы Битрикс24, данные ERPNext | логи контейнера, restart или откат |
| ERPNext frontend/backend | каталог, остатки и складские операции | CRM Битрикс24 и часть несвязанных экранов | `ping`, Compose status, логи ERPNext |
| MariaDB ERPNext | весь складской контур | Битрикс24 | не пересоздавать volumes, готовить восстановление |
| OAuth/права пользователя | отдельные действия дают отказ | операции, на которые права есть | проверить пользователя и scope приложения |
| Диск Битрикс24 | загрузка документов и внешняя копия бэкапа | складские проводки и локальный бэкап | проверить REST-ошибку и локальный файл |

## Сигналы

- `GET /health` подтверждает только процесс backend, но не доступность ERPNext и Битрикс24.
- `GET http://127.0.0.1:8080/api/method/ping` подтверждает HTTP ERPNext, но не корректность конкретной проводки.
- Успешный HTTP-ответ записывающего маршрута должен содержать ID созданного документа.
- Таймаут после отправки запроса требует проверки документа по ID, времени и основанию.

## Восстановимость

- Код и конфигурационные образцы — Git.
- Секреты — отдельные env-файлы сервера.
- Данные ERPNext — Docker volumes и бэкапы.
- CRM-данные — Битрикс24.
- Предыдущий образ и контейнер backend сохраняются при деплое.

## Запрещённые аварийные действия

- удаление Docker volumes;
- повторная миграция каталога поверх рабочего ядра;
- массовое удаление дублей без отчёта;
- восстановление БД без фиксации выбранного дампа;
- многократное нажатие записывающей кнопки после таймаута.

Пошаговые команды — в [SOS.md](SOS.md).
